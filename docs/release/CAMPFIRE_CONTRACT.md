# Campfire server contract

Local candidate, 2 November 2026. Migration `20261101201444_campfire_authority_and_moderation.sql` has not been deployed by this task. Polling replaces public client-authored Realtime gameplay commands. Free and Pro members use the same authorization boundary. No paid entitlement is granted by any social operation.

## API

User RPCs are `public` schema functions executable only by `authenticated`. The actor always comes from `auth.uid()` and must still exist in `auth.users`; real Supabase anonymous auth identities and suspended accounts fail. Client table reads/writes, internal helpers and moderator-role assignments are denied. Application service-role keys must never enter the client.

| RPC | Parameters | Result |
| --- | --- | --- |
| `campfire_create_v1` | `p_request_id uuid`, `p_name text`, `p_display_name text`, `p_duration_minutes integer`, `p_mode text`, `p_animal text` | Snapshot |
| `campfire_join_v1` | `p_invite text`, `p_display_name text`, `p_animal text` | Snapshot |
| `campfire_read_v1` | `p_room_id uuid` | Snapshot |
| `campfire_command_v1` | `p_room_id uuid`, `p_request_id uuid`, `p_expected_revision integer`, `p_command text`, `p_mode text default null` | Snapshot; `leave` instead returns `{id, revision, left:true}` |
| `campfire_report_v1` | `p_room_id uuid`, `p_target_user uuid`, `p_reason text` | `{id:uuid}` |
| `campfire_block_v1` | `p_target_user uuid`, `p_blocked boolean default true` | `{blocked:boolean}` |
| `campfire_moderator_status_v1` | None | Boolean |
| `campfire_moderator_queue_v1` | None | Array of up to 100 oldest unresolved reports |
| `campfire_moderate_v1` | `p_report_id uuid`, `p_action text`, `p_note text` | `{resolved:true}` |

Snapshot: `{id, code, name, durationMinutes, mode, status, revision, startedAt, severedBy, myParticipantId, participants}`. `code` is a unique 32-hex-character invite token (128 bits from a cryptographic digest of two independently generated UUIDs); `id` and `myParticipantId` are UUIDs. Participants are `{id,name,animal,species:'oak',isHost,status,joinedAt}`, with `id` equal to their authenticated user ID. Left, suspended and blocked identities are excluded; `severedBy` is always null so that later blocking cannot leak a stored participant name. Roles and status never come from Presence or client-supplied JSON. Polling may show a state transition one poll interval later; use `startedAt` to align the local clock.

Modes: `shared_destiny`, `gentle_circle`. Animals: `fox`, `bunny`, `koala`, `bird`, `bee`. Duration: 5..180 minutes. Maximum 8 visible members. Room expires six hours after creation. Only lobby joins are allowed. Active membership in another current room prevents creating/joining another. Create requests are deduplicated by `(host,request_id)`; command requests by `(actor,request_id)`. Reusing a command request ID for a different room/command/mode fails. Keep IDs across transport retries; generate a fresh ID for a new intention.

Commands: `start`, `mode`, `leave`, `abandon`, `complete`. Only the actual host can start/change mode, and only in a lobby. `mode` needs `p_mode`; `start` uses the persisted duration/mode. Every accepted command increments revision exactly once. A revision mismatch fails with `Revision conflict`; refetch and let the user retry a changed intention. Completion changes only the caller, requires elapsed server time, and completes the room once no members remain focusing. An active shared-destiny departure/abandonment severs the room. Gentle-circle departure/abandonment leaves peers active; host leaving the lobby closes that lobby. Leaving revokes membership and returns no participant data, including on retries. Server actor locks and room-row locks serialize membership/transition mutations. Limits: 10 created rooms/hour, 60 accepted commands/minute, 10 reports/day per actor.

Errors are Postgres exceptions (`P0001`, or constraint/privilege errors for invalid inputs). Examples: `Authentication required`, `Account suspended`, `Membership required`, `Host required`, `Room closed or unavailable`, `Room blocked`, `Revision conflict`, `Focus duration not elapsed`, `Invalid or abusive content`. Treat database read denials as access loss and clear the local room; never fall back to a simulated room. Transport failure must be visibly stale/disconnected and must not fabricate success. Guard callbacks by authenticated owner and channel/poll generation, and clear storage/memory on logout, deletion or account change.

## Moderation

Room names have 1..80 characters, display names 1..40; controls are rejected. Server-side normalized filtering rejects a bounded English/Indonesian abusive-term list, including punctuation/spacing/full-width obfuscation. This is a baseline filter, not a claim of complete language coverage; reporting and owner review remain essential. Reasons and moderator notes have 3..500 characters. Do not show reports/notes publicly.

Reports require membership and an actual distinct room participant as target. Evidence is captured by the server at submission: canonical room state without the invite token, plus server-captured `hostId` so host deletion still redacts evidence after room pruning. Users cannot query, update or delete report evidence. Queue entries: `{id,reporter_id,target_id,room_id,reason,evidence,created_at,resolved_at}`. Actions: `dismiss` resolves without restriction; `remove` removes the target from the reported room and closes it; `suspend` denies the target all Campfire access and removes them from every room. When the target is the host, the room name is replaced by `Campfire`. Each decision has a persistent moderator/action/note timestamp record; an already-resolved report is idempotent. Server authorization checks apply regardless of what UI is visible.

Blocking stores an owner-target pair; joins check either block direction against every historical room participant. The blocker leaves all rooms currently shared with the target. A blocking host's room closes and its name becomes `Campfire`; an active shared-destiny room severs. Snapshots omit blocked identities. Unblock does not restore membership. Report before blocking if both actions are chosen, because blocking removes the reporter's membership.

Owner onboarding is a **trusted operational step**: identify the owner's verified auth UUID privately, then insert it into `public.campfire_moderators` using a trusted administrative channel. Never grant this role from a profile field, user metadata, JWT supplied role string, reviewer account or public function. No moderator has been assigned by this local implementation. Suspension reversal and moderator reassignment require the trusted administrative channel; these are not exposed to users.

Account deletion triggers trusted redaction before auth foreign keys cascade: reports where the user is reporter/target/room host/any captured participant lose their evidence and free-text reason; related action notes are replaced with a deletion marker. Moderator-authored action notes are also cleared if the moderator account is deleted. Other users cannot invoke this exception to evidence immutability. `campfire_maintenance_v1()` takes no arguments, is executable only by `service_role`, and deletes reports/action records older than 90 days and rooms expired for more than one day. **Schedule it daily through a trusted server job before production activation**, and document the 90-day maximum moderation retention in the public privacy policy. This task does not create a cloud job or change published policy. Rooms/requests automatically cascade with deleted owners; report subject/room references become null.

## Verification and rollout gates

Client integration polls every four seconds and gates the 20% social bonus on a runtime snapshot no older than ten seconds, matching owner/session ID/start/canonical end plus local pause accounting, and an own-member status of focusing/completed. Base offline focus rewards remain available. Durable state stores only optional `FocusSession.room_id` and an owner-scoped UUID pointer under `rimba_campfire_room_id:${owner}`; names are not persisted in this pointer. Logout clears visible state but preserves the owner pointer; verified leave/block/read denial deletes it. Recovery reads that pointer and local lifecycle history within the six-hour room window. Completed/abandoned local history reconciles a still-focusing canonical membership without minting another local reward. These client checks require final integration/device verification and do not establish anti-cheat against a modified client.

`tests/campfireDatabase.test.ts` uses PGlite and synthetic identities to exercise anonymous/outsider denials (including an actual anonymous auth row), table/helper/role escalation, canonical identity, host authorization, replay/revision conflicts, premature/elapsed completion, shared/gentle abandonment, leave retry privacy, normalized filtering, invite expiry/capacity, bidirectional block/unblock, private immutable reports, role-gated moderation, decision deduplication, account-deletion redaction and service-only retention pruning. It does not prove deployed grants, concurrent cross-connection behavior or native acceptance.

Before release: review/apply migration through the approved production workflow; inspect deployed table grants, RLS and function privileges; test the same adversarial matrix with disposable independent authenticated sessions; assign the verified owner moderator privately; exercise report -> queue -> remove/suspend/dismiss in the shipped UI. Verify two-device start/late-join denial/clock alignment/abandon/complete/reconnect, block privacy and owner switch/deletion. Confirm account deletion behavior and define operational moderation-evidence retention with the published privacy policy. Polling and server authorization do not by themselves prove that local focus rewards have trusted social-bonus provenance; client integration must avoid bonuses for fabricated/stale room strings. Keep SOCIAL-01 OPEN until these deployment, privacy, moderation-operation and device gates have evidence.
